# PinchTab Research Report

## Overview

PinchTab is a standalone, open-source HTTP server written in Go (12MB binary) that gives AI agents direct control over Chrome browsers. Created in mid-February 2026, it has rapidly gained traction (~6,400 GitHub stars in under a month) by solving a fundamental pain point in the AI agent ecosystem: browser automation tools are either framework-locked (Playwright requires Node, Browser Use requires Python, OpenClaw's browser backend only works inside its own ecosystem) or token-inefficient (screenshot-based approaches consume 10,000+ tokens per page). PinchTab's accessibility-tree-first approach reduces this to ~800 tokens per page — a 5-13x improvement.

The project is run by a GitHub organization (pinchtab) with 21 contributors and an active development cadence (234+ issues/PRs, most closed promptly, only 3 open at time of research). It has already spawned a vibrant ecosystem of community-built MCP wrappers, Claude Code skills, OpenClaw integrations, and even a security detection scanner. Media coverage spans Dataconomy, AIGazine, DEV Community, Bitdoze, and has been translated into 6+ languages.

PinchTab occupies a unique niche: it's the first browser automation tool designed from the ground up for AI agents rather than human QA testers. Its HTTP-first architecture means any language, any framework, or even plain `curl` can control a browser. Combined with stealth capabilities (fingerprint rotation, navigator.webdriver patching), persistent sessions, and multi-instance orchestration, it positions itself as foundational infrastructure for the agentic web.

## Technical Analysis

### Architecture
- **Runtime:** Single Go binary (12MB), no external dependencies
- **Protocol:** HTTP API on port 9867 (localhost-only by default), Chrome DevTools Protocol (CDP) under the hood
- **Process model:** Server (control plane) → Bridge (per-instance runtime) → Attach (external Chrome)
- **Installation:** curl script, npm, or Docker

### Key Capabilities
| Feature | Details |
|---------|---------|
| **Token efficiency** | `/text` ~800 tokens, `/snapshot?filter=interactive` ~3,600, full `/snapshot` ~10,500 |
| **Stable element refs** | Accessibility-based refs (e0, e5, e21) instead of fragile CSS selectors or coordinates |
| **Stealth** | Three levels (light/medium/full), fingerprint rotation, UA spoofing, navigator.webdriver patching |
| **Multi-instance** | Parallel Chrome processes with isolated profiles |
| **Persistent sessions** | Cookies, history, localStorage survive restarts |
| **Content blocking** | Ads, images, media blocking for speed |
| **IDPI** | Indirect Prompt Injection Defense — domain allowlisting, content protection |
| **MCP/SMCP** | Native MCP server with 21 browser tools over stdio JSON-RPC |
| **ARM64** | First-class Raspberry Pi support with Chromium auto-detection |
| **Dashboard** | React-based real-time web dashboard |

### API Design
- Read-only GETs for data, POSTs for mutations, all JSON
- CLI mirrors HTTP API: `pinchtab nav`, `pinchtab snap`, `pinchtab click`, `pinchtab text`
- Diff-based snapshots for multi-step workflows (`/snapshot?diff=true`)
- PDF export (zero token cost)

### Security Posture
- Defaults to localhost-only binding
- API token authentication
- Sensitive endpoints off by default
- IDPI enabled by default with local-only website allowlist
- **CVE-2026-30834** (High): SSRF via /download endpoint — patched in PRs #223, #227, #228
- **Helixar-AI "Unpinched"**: Third-party detection scanner published, indicating security community scrutiny of stealth capabilities
- Active CodeQL integration and security-focused PRs

- Security control verification tests
- Active issue triage (3 open out of 234+ total)
